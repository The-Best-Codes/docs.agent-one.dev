If a provider isn't built in, but it has an OpenAI-compatible API, you can add it as a **custom provider**. This works with self-hosted servers like vLLM, LiteLLM, and llama.cpp, and with company AI gateways.

## Add a Custom Provider

{/* prettier-ignore */}
<Steps>
<Step>

    ### Open the custom provider form

    Go to `Settings` -> `Providers` -> **Custom**, click **Add Provider**, and choose **OpenAI Compatible**.

</Step>
<Step>

    ### Fill in the details

    ![The Add OpenAI Compatible Provider dialog with Name, Base URL, API Key, HTTP Headers, and Models.](/images/docs/models/custom-provider-dialog.png)

    - **Name**: what the provider is called in the model selector.
    - **Base URL**: the API's base URL, usually ending in `/v1`, like `http://192.168.1.40:8000/v1`.
    - **API Key**: only if your API needs one.
    - **HTTP Headers**: any extra headers your API needs.

</Step>
<Step>

    ### Add models

    Click **Auto** to fetch the model list from your API's `/models` endpoint, or click **Add Model** to add models by ID.

    After fetching, you can edit each model's details, like its display name, context window, and whether it supports tools and images. See [Model Metadata](/docs/models/model-metadata).

</Step>
<Step>

    ### Save

    Click **Add Provider**. The provider and its models appear in the model selector.

</Step>
</Steps>

## Edit or Delete a Custom Provider

![The Custom providers card with an Add Provider button.](/images/docs/models/custom-providers.png)

Click the custom provider in `Settings` -> `Providers` -> **Custom** to change its name, URL, headers, or models. To remove it, click **Delete Provider** and confirm.

Custom providers stay on the computer you set them up on and don't sync.

## Tips

- If your server needs a path that isn't `/v1`, include it in the base URL.
- Turn on **Supports Tools** only for models that really support tool calling. Otherwise the model may answer with broken tool requests.
- For providers that are already built in, like OpenRouter or Groq, use the [built-in provider](/docs/models/built-in-providers) instead. It comes with model details and pricing.
