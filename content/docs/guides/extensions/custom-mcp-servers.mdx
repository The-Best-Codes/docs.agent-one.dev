---
title: Custom MCP Servers
description: Add your own STDIO or HTTP MCP servers to AgentOne that are not in the extension registry.
---

Custom extensions let you connect any MCP server to AgentOne - whether it is a server you wrote yourself, a server from a third-party project not yet in the registry, or an internal tool at your organization.

AgentOne supports two transport types for custom extensions:

- **STDIO (Local)** - a process that runs on your machine. AgentOne starts and manages it.
- **HTTP (Remote)** - a server reachable at a URL. AgentOne connects to it over HTTP.

SSE (Server-Sent Events) transport is not currently supported.

## Adding a Custom Extension

<Steps>
<Step>
### Open Extensions Settings

In AgentOne, click `Settings` -> `Extensions`, then click **Add Custom**.

</Step>
<Step>
### Choose a Server Type

Select either **STDIO (Local)** or **HTTP (Remote)** depending on how your server runs.

</Step>
<Step>
### Fill in the Details

**For STDIO servers:**

- **Command** - the executable and arguments that start the server. Common patterns include `npx -y @some/package`, `uvx some-tool`, or `docker run ...`.
- **Environment Variables** - any environment variables the server needs. These are passed to the process when it starts.
- **Timeout** - how long AgentOne waits (in seconds) for the process to start and respond before marking it as failed.

**For HTTP servers:**

- **URL** - the full URL of the MCP server endpoint.
- **Custom Headers** - any HTTP headers needed for authentication or routing.
- **Timeout** - same as above.

Both types also let you set **Requires Approval** as the default for all tools from this extension.

</Step>
<Step>
### Save the Extension

Click **Add Custom**. AgentOne adds the extension, attempts to start or connect to it, and lists its tools if the server responds successfully.

</Step>
</Steps>

## STDIO Server Examples

STDIO servers are the most common type. They run as local processes and communicate with AgentOne through stdin/stdout. A few typical command patterns:

```text
npx -y @modelcontextprotocol/server-filesystem /path/to/directory
uvx mcp-server-git
docker run -i --rm ghcr.io/some/mcp-server
```

If the server requires environment variables (for example, an API key), add them in the environment variables section rather than in the command string.

## HTTP Server Example

HTTP servers are useful for MCP servers deployed as web services - either hosted externally or running on your local network.

```text
https://mcp.example.com/mcp
```

Add any required authentication as a custom header, for example `Authorization: Bearer your-token`.

## Deep-Link Pre-Fill

If you click an `agent-one://mcp/install?...` link (from a project's README or a registry page outside the app), AgentOne opens the Add Custom dialog with the fields already filled in. You should still review every field before clicking Add. See [Deep Links](/docs/desktop-app/shortcuts-and-links/deep-links) for more on the link format.

## After Adding

Once added, the extension starts loading. If it connects successfully, you will see its tools listed when you open the extension's detail view. If it fails, open **Advanced** to see the error message and adjust the command, URL, or environment variables.

For troubleshooting help, see [Extensions Troubleshooting](/docs/desktop-app/troubleshooting/extensions).
