# Docs screenshots

Every image in `public/images/docs/` is generated by these scripts, so the whole set can be retaken whenever the app changes, and every image shares one annotation style.

## How it works

- **The real app, in a browser.** `serve-app.mjs` serves the AgentOne desktop frontend from a sibling checkout of [agent-one](https://github.com/The-Best-Codes/agent-one) with Vite. Before the app loads, `mock/setup.ts` replaces the Tauri backend: SQLite runs in the browser (`@sqlite.org/sqlite-wasm`) with the app's own migrations, secrets live in memory, and network requests are answered by the scene or proxied.
- **Scenes.** Each shot describes a scene: settings, a signed-in demo account (`lib/scene.mjs`), seeded chats (`lib/fixtures.mjs`), and mocked responses. Model data comes from a sibling checkout of [ai-model-directory](https://github.com/The-Best-Codes/ai-model-directory), and extensions come from a snapshot of the official MCP Registry (`fixtures/registry.sql.json`).
- **Annotations.** `lib/annotate.mjs` draws the window frame, highlight boxes, numbered markers, labels, and arrows into the PNG. Shots refer to elements with Playwright locators, so annotations follow the UI when it moves.
- **Website shots** (`shots/10-website.mjs`) load www.agent-one.dev and www.modeldirectory.dev directly and use a browser frame.

## Requirements

- Google Chrome (Playwright drives the installed copy)
- `../agent-one` with dependencies installed (`bun install`)
- `../ai-model-directory` (for `data/all.min.json`)

Override the locations with `AGENT_ONE_DIR` and `MODEL_DIRECTORY_DIR`.

## Usage

```bash
bun run screenshots:serve        # terminal 1: serve the app with the mock backend
bun run screenshots              # terminal 2: capture everything
bun run screenshots chats/       # or only shots whose id contains "chats/"
```

Set `RAW_DIR=/some/folder` to also save unannotated captures, including a screenshot of any shot that fails.

To refresh the extension registry snapshot:

```bash
node scripts/screenshots/snapshot-registry.mjs
```

## Annotation rules

Every image follows the same rules, and `capture.mjs` prints a warning when a shot breaks one:

- **Markers sit outside what they point at**, centered on one side of it (`anchor: "t" | "b" | "l" | "r"`). For tall or wide regions whose middle is busy, `align: "start" | "end"` moves the marker toward one end of that side.
- **Boxes** (`h.box`) outline one element or region. Boxes never touch or overlap each other.
- **Pins** (`h.pin`) are for things that sit next to each other, like menu items or icon rows: a marker with a short leader line and no outline. `leader` sets the line length when the marker needs to clear a border.
- **Nothing covers the UI.** After rendering, the pixels under every marker are checked; a marker over text, icons, or borders produces a warning.
- **Crops grow to fit markers**, and should end on blank space or at a natural edge, never mid-row.

Warnings look like `⚠ chats/attachments: marker 1 covers UI content`. Fix the shot until a full run prints none.

## Shot options

| Option                             | What it does                                                                                                                                                             |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `route` / `url` / `html` / `image` | What to capture: an app route, a website, an HTML snippet, or a file in `sources/`                                                                                       |
| `scene`                            | Settings, account, chats, and mocked responses (see `lib/scene.mjs`)                                                                                                     |
| `viewport`, `theme`                | Window size and light or dark theme                                                                                                                                      |
| `prepare(page, h)`                 | Clicks and typing before the capture                                                                                                                                     |
| `crop(page, h)`                    | The area to keep; `h.rect`, `h.column` (chat column width), and `h.visible` help                                                                                         |
| `annotate(page, h)`                | Returns `h.box`, `h.pin`, and `h.marker` annotations. Use `h.text(locator)` to target a link's text rather than its full-width element, and `h.all(locator)` for a group |
| `isolate`                          | Shows a dialog or popover on the app's plain dimmed backdrop, without the blurred page behind it                                                                         |
| `hideMain`                         | Blanks the chat pane, for sidebar shots                                                                                                                                  |
| `reducedMotion`                    | Stops hover marquees from scrolling titles mid-capture                                                                                                                   |
| `css`                              | Extra CSS, for example to hide the message box                                                                                                                           |

## Adding a shot

Add an entry to a file in `shots/`. The `id` is the output path under `public/images/docs/`.

```js
{
  id: "chats/example",
  route: "/chat/chat-lisbon",          // app route (or `url` for a website)
  scene: withChats(),                   // what the app should contain
  prepare: async (page) => {},          // click things before the capture
  crop: async (page, h) => h.rect(page.getByRole("dialog"), 24),
  annotate: async (page, h) => [
    await h.box(page.getByRole("button", { name: "Send message" }), "1", { anchor: "b" }),
  ],
}
```

In the page text, describe the markers as a numbered list directly under the image, in the same order. An image without markers shouldn't be followed by a numbered list.
